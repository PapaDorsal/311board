# ChiWardBoard

[chiwardboard.com](https://chiwardboard.com) ranks Chicago's 50 wards by how
fast the city closes 311 service requests filed in them. Every figure comes
from the City of Chicago's public 311 dataset, computed at build time and
published as a dated snapshot. The site is static: no server code, no
accounts, and the page makes no live calls.

The voice and the rules the numbers follow are in `docs/design-brief.md`. The
methodology a visitor sees is on `about.html` and, per type, on the board.

## Layout

| Path | What it is |
| --- | --- |
| `index.html`, `assets/app.js` | The board: hook, map, ranked table, methodology, ward finder. |
| `ward.html`, `assets/ward.js` | The per-ward report card template. |
| `ward-1.html` .. `ward-50.html` | Generated from `ward.html` so link previews name the ward. Do not edit by hand. |
| `assets/app.css` | One stylesheet, light and dark. |
| `assets/og.png`, `assets/og/ward-N.png` | Share cards. The per-ward cards carry no figures on purpose (see `tools/build-ward-og.mjs`). |
| `data/leaderboard.json` | The rolling 12-month snapshot. `leaderboard-2024.json` and `-2025.json` are the calendar years. |
| `data/wards.geojson`, `data/streets.geojson` | Ward outlines and arterial streets for the map. |
| `data/ward-neighborhoods.json` | Which community areas each ward's requests come from. |
| `data/address-index.json` | Hundred-block to ward index, so an address resolves in the browser. |
| `tools/` | The build scripts below. `spike-311*.mjs` and `311-findings*.md` are the original feasibility work. |

## Rebuilding

Node 22 or later. No dependencies except for the two share-card scripts, which
need Playwright.

```sh
# The three snapshots. The rolling window is computed from today's date:
# twelve complete months ending at the first of the current month.
node tools/build-data.mjs
WINDOW_FROM=2024-01-01 WINDOW_TO=2025-01-01 node tools/build-data.mjs   # then mv to leaderboard-2024.json
WINDOW_FROM=2025-01-01 WINDOW_TO=2026-01-01 node tools/build-data.mjs   # then mv to leaderboard-2025.json

# Refuse a malformed snapshot. Pass the previous file to catch a half-failed fetch.
node tools/check-snapshot.mjs data/leaderboard.json previous.json

# The fifty ward pages, from ward.html and the snapshot.
node tools/build-ward-pages.mjs

# Rarely: map geometry, neighbourhood context, address index, share cards.
node tools/prep-wards-geo.mjs
node tools/prep-streets-geo.mjs        # see tools/README-streets.md
node tools/build-neighborhoods.mjs
node tools/build-address-index.mjs
node tools/build-og.mjs && node tools/build-ward-og.mjs   # needs playwright
```

`.github/workflows/refresh-data.yml` runs the first three steps on the 2nd of
every month and commits straight to `main` if the snapshots pass the check.
The rolling build is additionally required to end at the first of the current
month, so a window that stops rolling fails the run instead of shipping.

## Things that need a human

- **Ward office overrides.** `OFFICE_FIXES` in `tools/build-data.mjs` corrects
  links the city's directory gets wrong. The build audits every ward website
  and prints a warning for any that stop resolving; it never edits on its own.
- **Street sweeping link.** The city's schedule page is year-specific
  (`street_sweeping2026.html`); bump it in `index.html` each January. The ward
  pages copy that block at build time.
- **Share cards.** The unattended refresh has no browser, so the PNGs are only
  regenerated by hand. They carry no figures for exactly that reason.
- **New calendar year.** Add it to `WINDOWS` in both `assets/app.js` and
  `assets/ward.js`, add a rebuild step to the workflow, and mention it on
  `about.html` and the board's "what's on the board" note.
